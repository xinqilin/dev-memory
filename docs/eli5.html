五歲小孩也看得懂的版本

把開發時的對話，
變成全隊查得到的百科

每個人的電腦會自動記日記。你覺得夠了，就把日記整理成卡片，投稿到團隊圖書館。隊友同步回去，就查得到。

它怎麼運作

第 1 步

自動記日記

你在 Claude Code 或 Codex 裡的對話，會自動存進你自己的電腦。只有你看得到。

第 2 步

整理成便條卡

覺得資料夠了，就下 /wiki-ingest。一張卡只寫一件事：為什麼要做、決定怎麼做、放棄了哪個做法。

第 3 步

放進團隊百科

AI 把卡片放到對的頁面，頁面分成三類：功能、資料表、repo。舊的說法被推翻時，會自動標出來。

第 4 步

投稿、檢查、上架

要你自己按寄出（push + 開 PR）。系統先自動檢查有沒有夾帶密碼，同事看過才會上架。

第 5 步

隊友同步回自己電腦

隊友把圖書館同步到自己電腦，就能搜到全隊的記憶，而且不用連到任何伺服器。

記住四件事

圖書館才是正本

GitHub 上的團隊 repo 是正本。你電腦裡的資料庫只是索引，壞了或換電腦，重建一份就好。

整串當成一塊 發票作廢流程 搜「作廢」✕ 找不到
兩個字切一塊 發票票作作廢廢流流程 搜「作廢」✓ 找到

中文要切成小積木

中文每兩個字切成一塊，搜尋才找得到。你現在的 claude-mem 搜「例外」只找到 1 筆，實際上有 10 筆。

跨 repo：資料表是十字路口

每張資料表、每支 API 都有自己的一頁，寫著哪些 repo 在讀、哪些在寫，一看就知道改了會影響誰。圖上的關係只是範例。

兩支筆，同一本日記

同一個 plugin，Claude Code 和 Codex 都能裝。兩邊寫進同一份記憶，換工具也不會失憶。

會用到的東西

每個人的電腦

Claude Code 或 Codex CLI 寫日記的筆，也是幫你整理卡片的 AI。不需要另外申請 LLM API key。 已經有
dev-memory plugin 記日記的小幫手，也就是這次要寫的東西。包含自動記錄、/wiki-ingest 這些指令，以及搜尋功能。 從 marketplace 安裝
Bun 讓小幫手跑起來的引擎，用它執行 plugin 程式。 brew install bun
SQLite 抽屜裡的索引卡盒。整個資料庫只是一個檔案（~/.dev-memory/memory.db），不用開伺服器，中文搜尋靠它。 Bun 內建，不用裝
git + gh 郵差：負責同步團隊 repo、開 PR。用自己的 GitHub 帳號登入就好，不用自己產生 PAT，PR 作者也會是你本人。 brew install gh + gh auth login

團隊共用（只要建一次）

團隊記憶 repo 團隊圖書館，也就是正本。裡面有卡片、百科、規則，以及產品和 repo 的對照表。 GitHub 私有 repo
project-plugin repo 小幫手的發放處，隊友從這裡安裝 plugin。 GitHub 私有 repo
GitHub Actions + gitleaks 門口警衛：每個 PR 自動檢查格式、壞掉的連結，以及有沒有夾帶密碼。 在 CI 跑，個人不用裝

以後有需要才加

向量搜尋 用 Bedrock Cohere Embed v4 或 bge-m3，讓搜尋也能比對「意思相近」的內容。 測出搜尋不夠準才加
PostgreSQL + pgvector 放在 RDS 的中央搜尋服務。 PM 等不用 CLI 的人要網頁搜尋時才加
Google Chat 通知 有新 PR 時通知大家，可以用 GitHub for Google Chat app 或一個 Action 做到。 想保留通知才加

這次不用的東西

claude-mem退休：中文搜不到，還會把決定漏掉
n8n + Apps Script改成直接開 PR，步驟更少
PostgreSQL先不用，真的需要時再加
完整規格、實作步驟和驗證方式都寫在計畫檔裡。
