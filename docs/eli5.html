一段對話，
怎麼變成全隊的百科

開發過程中的決定，自動變成全隊查得到的文件。七個步驟現在都跑得起來，已經走完一次真實的 PR。

記日記→ 搜得到→ ① 挑卡片→ ② 排計畫→ ③ 審核頁→ 你按送出→ 隊友同步

藍框是要你點頭的確認點；綠色那一步只有你能做。

為什麼要做

記憶會蒸發

對話紀錄預設 14 天就清掉。半年後想問「當初為什麼這樣決定」，沒有人答得出來，只能重新踩一次坑。

文件是額外工作

做完功能還要再寫一次文件，沒有人有動力。寫完了，程式碼一改又過期，也沒人回去更新。

知識散在各個 repo

一個功能橫跨 batch、api、frontend。改了一張資料表，誰在讀它、會影響誰，得靠人記。

原本的工具搜「例外」 找到 3 筆 ✕ 漏了 9 筆
實際上有 12 筆 ✓ 現在 12 筆全中

搜不到就等於沒有

原本的記憶工具不會斷中文，搜「例外」只找到 3 筆，實際有 12 筆。找不到的記憶，跟沒記一樣。

它怎麼運作

第 1 步

自動記日記

每講完一回合，對話就存進你電腦裡的 memory.db。原始對話只留在你這台。

存進去時，中文兩個字一塊 例外外處處理
查「例外」 例外 找到 12 筆，跟逐字比對一樣多
程式名字整個留著，也拆開 sapStatus→ sapstatus
第 2 步

中文也搜得到

問 AI 以前做過什麼，它會先翻這本日記。中文、英文、程式名字混在一起也找得到。

第 3 步確認點 ①

挑出重點卡片

叫 /mem-save 或 /wiki-ingest，AI 把對話濃縮成卡片：為什麼、決定什麼、放棄什麼。你刪改後才留下。

第 4 步確認點 ②

排好整理計畫

AI 列出要新增哪幾頁、更新哪幾頁、哪個舊決定被換掉。你點頭，它才動筆。

第 5 步確認點 ③

在審核頁改到滿意

瀏覽器自動打開本機審核頁。一次看全部頁面、跟 main 比、看每句話的來源卡片。你改、叫 AI 改、用 IDE 改都行。

第 6 步

你自己按送出

在審核頁按「送出 PR」，或自己打 dev-memory publish。PR 作者是你本人。AI 從頭到尾不會替你 push。

第 7 步

隊友同步，就搜得到

PR 合併後，隊友 sync 一下，不管用 Claude Code 還是 Codex，都查得到你的決定。

資料從哪來、存到哪

同一份內容會換三種身分：對話 → 卡片 → 頁面。每次換身分都有人點頭。

① 蒐集：檔案 → 資料庫

Stop hook 每回合從上次讀到的位置往下讀，濾掉工具輸出跟系統訊息，只留你跟 AI 真的說的話。原文存一份，另外切詞存一份給搜尋用。

② 產出：資料庫 → 檔案

卡片匯出成 JSONL，AI 把頁面寫在另一個工作目錄裡（你自己的 clone 完全不動）。審核頁看的是檔案，不是資料庫，所以你在頁面上改、用 IDE 改、叫 AI 改，改的都是同一份。

③ 回流：檔案 → 資料庫

PR 合併後，sync 直接讀 main 上的版本（不是讀別人硬碟上的工作檔），寫回本機的卡片跟頁面，再切一次詞進索引。被取代的頁面留著，但不會出現在搜尋結果。

這一步資料從哪來存到哪
自動記錄 對話紀錄檔，從上次讀到的位置往下讀 turn 表（原文）＋ fts（切過詞）
搜尋 你的問句，一樣先切詞 不存，只回結果；片段取自原文，不是切過的內容
存卡片 AI 從對話萃取，你確認過的版本 record 表，狀態 local
整理 wiki 搜尋結果（卡片＋對話）＋ repo 裡的 schema.md 規則 worktree 裡的 wiki/*.md；卡片匯出成 records/*.jsonl，狀態轉 submitted
審核頁 worktree 的檔案；「跟 main 比較」來自 git 上的版本；「來源紀錄」才去本機資料庫撈卡片 直接寫回檔案（停止打字 800ms 自動存）
核准 / 送出 PR worktree 的檔案 commit 在 worktree；送出才 push 並開 PR
CI PR 裡的檔案 不存，只擋：機密掃描＋結構檢查
隊友同步 main 上的版本（用 git 直接讀，不碰別人的工作檔） record（merged）、page，再進 fts

切詞做兩次，而且只做在索引跟查詢上。 存進資料庫的永遠是原文；另外存一份切過詞的給搜尋比對用。查詢時把問句用同樣方式切一次，兩邊才對得起來。所以你看到的搜尋片段是人看得懂的原文，不是「拋例 例外 外要」那種切碎的東西。

本機資料庫隨時可以刪。 正本在團隊 repo，原始對話還在你自己的硬碟上。刪掉重建就好，這也是為什麼不把資料庫檔案提交上去。

哪一步在哪裡做

對話裡只挑內容、對計畫。真正的編輯跟審核在瀏覽器，不是在對話視窗裡。

存決策、挑卡片、對整理計畫確認點 ① ②，一句話回覆就好 對話裡
AI 寫頁面寫在獨立的 worktree，你自己的 clone 完全不受影響 磁碟上
編輯、預覽、跟 main 比對、看來源、核准、送出確認點 ③，本機網頁，只綁 127.0.0.1 瀏覽器
CI 檢查與 mergegitleaks 掃全 repo，結構檢查只掃 wiki 跟 records GitHub
隊友把記憶拉回本機一個指令：sync 終端機

審核頁、IDE、對話三種改法改的是同一個檔案；同時改到會跳出「重新載入 / 保留我的版本」，不會默默蓋掉。

為什麼中間要有一層 wiki

紀錄不是文件

一年下來幾千則紀錄沒人讀得完。中間這層由 LLM 整理成一頁一個主題，人跟 AI 都先讀它，讀不夠再往下挖原始紀錄。

互相連結，舊的會被標掉

每次 ingest 會同時更新總目錄跟相關頁面；被推翻的決定不刪掉，標成「已被取代」，搜尋時不會再跳出來誤導人。

記住幾件事

圖書館才是正本

GitHub 上的團隊 repo 是正本。你電腦裡的資料庫只是索引，壞了或換電腦，重建一份就好。

整串當成一塊 發票作廢流程 搜「作廢」✕ 找不到
兩個字切一塊 發票票作作廢廢流流程 搜「作廢」✓ 找到

中文要切成小積木

中文每兩個字切成一塊，搜尋才找得到。同一份資料，原本的斷詞搜「例外」只找到 3 筆，切成小積木後 12 筆全中。

跨 repo：資料表是十字路口

每張資料表、每支 API 都有自己的一頁，寫著哪些 repo 在讀、哪些在寫，一看就知道改了會影響誰。圖上的關係只是範例。

兩支筆，同一本日記

同一個 plugin，Claude Code 和 Codex 都能裝。兩邊寫進同一份記憶，換工具也不會失憶。

會用到的東西

每個人的電腦

Claude Code 或 Codex CLI 寫日記的筆，也是幫你整理卡片的 AI。不需要另外申請 LLM API key。 已經有
dev-memory plugin 記日記的小幫手，也就是這次要寫的東西。包含自動記錄、/wiki-ingest 這些指令，以及搜尋功能。 從 marketplace 安裝
Bun 讓小幫手跑起來的引擎，用它執行 plugin 程式。 brew install bun
SQLite 抽屜裡的索引卡盒。整個資料庫只是一個檔案（~/.dev-memory/memory.db），不用開伺服器；刪掉可以從正本重建。 Bun 內建，不用裝
git + gh 郵差：負責同步團隊 repo、開 PR。用自己的 GitHub 帳號登入就好，不用自己產生 PAT，PR 作者也會是你本人。 brew install gh + gh auth login

團隊共用（只要建一次）

團隊記憶 repo 團隊圖書館，也就是正本。直接沿用既有的文件 repo，原本的文件不動，只在旁邊加上卡片、百科、規則跟對照表。 GitHub 私有 repo
dev-memory repo 小幫手的發放處，隊友從這裡安裝：dev-memory@104mis-plugins。 GitHub 私有 repo
GitHub Actions + gitleaks 門口警衛：每個 PR 自動檢查格式、壞掉的連結，以及有沒有夾帶密碼。 在 CI 跑，個人不用裝

以後有需要才加

向量搜尋 自己裝 Ollama，選 qwen3-embedding 或 bge-m3，讓搜尋也能比對「意思相近」的內容。用 /mem-setup 選，預設不裝。 使用者自己選要不要裝
PostgreSQL + pgvector 放在 RDS 的中央搜尋服務。 PM 等不用 CLI 的人要網頁搜尋時才加
Google Chat 通知 有新 PR 時通知大家，可以用 GitHub for Google Chat app 或一個 Action 做到。 想保留通知才加

選配：意思相近也找得到
